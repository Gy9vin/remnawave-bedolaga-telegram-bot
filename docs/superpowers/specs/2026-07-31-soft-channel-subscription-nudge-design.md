# Мягкая обязательная подписка + пуш свежего поста — дизайн

**Дата:** 2026-07-31
**Статус:** дизайн утверждён владельцем, готов к плану
**Репозитории:** `remnawave-bedolaga-telegram-bot` (backend `app/`) + `bedolaga-cabinet` (frontend `src/`)
**Отдельная фича (после этой):** резервный метод входа при оплате — своя спека.

## Проблема / цель
У канала ~10k подписчиков, но пост смотрят ~2k — низкий охват. Прежняя «обязательная подписка» была жёсткой: при отписке отключала VPN (выкидывала из сквада). Нужно: (1) **мягко** гнать всех в подписчики, НЕ отключая VPN; (2) **поднимать реальные просмотры** — гнать активную аудиторию бота/кабинета к свежему посту; (3) не раздражать повтором — показывать каждое уведомление один раз (пока не выйдет новый пост).

Заставить *читать* пост нельзя (Telegram не даёт форсить/проверять прочтение) — поэтому цель: подписать всех мягко + приводить активную аудиторию к посту.

## Решения (утверждены владельцем)
- **Гейт меню в боте** (не подписан → экран «подпишись + проверить», меню закрыто), **VPN никогда не отключаем** (мягкий режим).
- **Мягкий режим — глобальный, по умолчанию ВКЛ.**
- **Источник поста — авто из ГЛАВНОГО канала** (бот-админ ловит `channel_post`). Доп-каналы на новости не мониторим.
- «Главный канал» — флаг `is_main` с тумблером в админке кабинета (сейчас главный = sort_order 0).
- **Пост показываем ВСЕМ** (если есть новый непросмотренный); блок «подпишись» — **только неподписанным** (и email-only, чью подписку проверить нельзя — «у них тоже есть телеграм»).
- **Отметка «видел»** (`last_seen_channel_post_id`): каждое уведомление показывается один раз, до следующего поста.

## Данные (модель + миграция)
- `RequiredChannel`: добавить `is_main: bool` (default false), а также поля свежего поста главного канала: `last_post_message_id: int|null`, `last_post_link: str|null`, `last_post_title: str|null` (короткий текст/заголовок), `last_post_at: datetime|null`.
- `User`: добавить `last_seen_channel_post_id: int|null` (id последнего поста, который юзер уже видел в попапе/карточке).
- Глобальная настройка `CHANNEL_SOFT_MODE: bool` (в `app/config.py`, default `True`): в мягком режиме `channel_checker` НЕ вызывает `deactivate_subscription`/`disable_remnawave_user`.
- Alembic-миграция под новые колонки (в диапазоне нашего паттерна `9\d{3}` или upstream-совместимо — использовать существующий стиль репо).

## Backend (бот, `app/`)
1. **Ловля постов главного канала:** хендлер апдейтов `channel_post` (aiogram). Если `channel_post.chat.id` == `channel_id` главного (`is_main=true`) required-канала → обновить `last_post_message_id`, `last_post_link` (сформировать t.me-ссылку на сообщение), `last_post_title` (первые ~120 символов текста/caption или "Новый пост"), `last_post_at`. Требует, чтобы бот был админом канала (авто-источник).
2. **Мягкий гейт:** в `app/middlewares/channel_checker.py` / `channel_subscription_service.should_disable_subscription` — при `CHANNEL_SOFT_MODE=True` НИКОГДА не деактивировать (ни trial, ни paid); экран-гейт «подпишись + проверить» остаётся, меню закрыто до подписки. Логику `_deactivate_subscription_on_unsubscribe` в мягком режиме не выполнять.
3. **Карточка свежего поста (бот):** после прохождения гейта, если у главного канала есть `last_post_message_id` и он `!= user.last_seen_channel_post_id` — показать сообщение «🆕 Свежее в канале: {title} [Открыть пост]» (кнопка-ссылка на `last_post_link`). После показа/клика — `user.last_seen_channel_post_id = last_post_message_id`.
4. **Cabinet API — эндпоинт нуджа:** `GET /cabinet/channel-nudge` → `{ needs_subscribe: bool, channel: {title, link} | null, latest_post: {link, title, id} | null, show_post: bool }`.
   - `needs_subscribe`: true, если пользователь НЕ подтверждён как подписанный на главный канal. Для юзера с `telegram_id` — проверка членства (`check_user_subscriptions`, только главный канал); для email-only (нет `telegram_id`) — всегда `true` (проверить нельзя → считаем не подписан).
   - `show_post`: true, если `latest_post.id` существует и `!= user.last_seen_channel_post_id`.
   - `latest_post` берётся из главного канала.
5. **Отметка seen из кабинета:** `POST /cabinet/channel-nudge/seen` (или флаг в GET) — устанавливает `user.last_seen_channel_post_id = latest_post.id`. Вызывается фронтом при показе/закрытии попапа.

## Frontend (кабинет, `src/`)
6. **API** `src/api/*`: `getChannelNudge()` и `markChannelPostSeen(postId)`.
7. **Попап при входе:** мягкая закрываемая модалка (не блокирует кабинет), рендерится при загрузке кабинета, если `show_post` ИЛИ `needs_subscribe` (и попап по этому посту ещё не помечен seen):
   - **Пост (всем, если `show_post`):** «🆕 Свежее в канале: {title}» + кнопка «Открыть пост» (ссылка `latest_post.link`).
   - **Подписка (только если `needs_subscribe`):** «Обязательно подпишись на наш канал, чтобы быть в курсе новостей!» + кнопка «Подписаться» (ссылка `channel.link`).
   - При показе/закрытии → `markChannelPostSeen(latest_post.id)` (если пост есть), чтобы больше не выскакивало до следующего поста. Открыл ЛК 2 раза в день без нового поста → попап не появляется.
   - Жёсткий `ChannelSubscriptionScreen` для этого сценария НЕ показываем (мягкий режим бэкенда не отдаёт блок-ошибку).
8. **Админка каналов** (`src/pages/AdminChannelSubscriptions.tsx` + `src/api/adminChannels.ts`): тумблер **«Главный канал»** (`is_main`) на строке канала; при включении у одного канала — снимать у остальных (ровно один главный). Показать (read-only) свежий пост главного канала, если есть.

## Обработка ошибок / крайние случаи
- Нет главного канала / нет постов → `latest_post=null`, `show_post=false`; попап только с подпиской для неподписанных (если решим показывать без поста — throttle отдельным «видел подписку»; для MVP: без поста попап не навязываем, показываем при первом входе через seen=null). Уточнение: если `latest_post=null` и `needs_subscribe`, показать попап-подписку один раз (seen помечать отдельным маркером/`last_seen_channel_post_id=0`).
- Панель/Telegram недоступны при проверке членства → трактуем как «не подтверждён подписан» (мягко покажем нудж), не 500.
- Бот не админ канала → `channel_post` не приходит, `last_post_*` пустые; фича деградирует до «только подписка», без падений.
- Ровно один `is_main` канал — гарантировать на уровне API (при set is_main сбрасывать у прочих).

## Тестирование
- **Backend unit:** `channel_post` главного канала обновляет `last_post_*`; НЕ-главного — игнор. В `CHANNEL_SOFT_MODE=True` `should_disable_subscription`/деактивация не срабатывает (ни trial, ни paid). `/channel-nudge`: подписан → `needs_subscribe=false`; email-only → `true`; `show_post` по seen. `/seen` пишет `last_seen_channel_post_id`. Гарантия одного `is_main`.
- **Frontend:** сборка `tsc`+`build`+`vitest`; попап показывается при `show_post`/`needs_subscribe`, закрытие вызывает seen; не показывается, когда `last_seen == latest_post.id`; админ-тумблер «Главный канал» шлёт `is_main`.
